# 后端领域地图

## 阅读时机

修改 Spring Boot API、领域服务、缓存、事件、后台任务或可选 AI 能力前阅读本章。进入代码后继续遵守[后端局部规则](../../apps/server/AGENTS.md)。

## 读完能回答的问题

- 当前改动属于哪个领域，入口类、权威状态和下游依赖在哪里？
- 22 个顶级 Java 包如何归入稳定领域边界？

## 领域边界

源码根目录为 `apps/server/src/main/java/com/chtholly`。当前 22 个顶级包全部归入以下七个领域；领域是维护视角，不要求目录物理合并。

| 领域 | 顶级包 | 职责边界 |
|------|--------|----------|
| 账号治理 | `auth`、`user`、`profile`、`admin` | 登录注册、JWT 与刷新令牌、公开资料、本人资料、角色、封禁和管理员审计 |
| 内容生产 | `post`、`tag`、`comment`、`storage`、`content` | 草稿到发布、正文对象、标签、评论，以及供推荐/Agent 共享的内容智能契约 |
| 社区互动 | `counter`、`relation`、`notification`、`recommendation` | 点赞收藏、关注关系、站内通知和个性化推荐 |
| 内容发现 | `search`、`bangumi`、`cache` | 全文索引与 Hub 查询、Bangumi 外部数据、多级缓存基础件 |
| Agent 平台 | `agent`、`llm` | WebSocket Agent、上下文/工具/记忆/观测，以及模型、Embedding 和 RAG 适配 |
| 内容初始化 | `seed` | 可重复执行的账号、文章、互动和 Bangumi 初始化数据生成 |
| 平台基础 | `common`、`config`、`health` | 通用异常/分页/限流/Kafka 基础、全局 Bean 配置和健康检查 |

## 应用层与适配器边界

后端采用兼容门面下的渐进式应用层：HTTP/WebSocket 适配器只解析协议、提取认证身份并映射响应；公开 Service 门面负责保持既有调用契约；按用例拆分的命令/查询服务编排事务、策略与窄基础设施端口。Controller 不得直接访问 Mapper、Redis、Kafka 或 Elasticsearch 客户端，Mapper 也不得反向依赖 API/Service。

这一边界由 `BackendArchitectureFitnessTest` 持续执行：禁止字段注入和新的适配层越界，并为 Spring 构造依赖与生产源码长度设置“全局上限 + 精确遗留预算”。预算用于阻止已治理入口重新膨胀，不要求把 Trace 聚合、DTO 投影或专用算法按行数机械拆散。兼容门面可以保留原接口，但不得保留测试专用的大构造器或在生产源码中手工拼装完整对象图。

代表性应用服务包括认证的注册/登录/Token/密码恢复用例、文章的草稿/元数据/发布/删除与 Feed 查询、关系的命令/查询/投影缓存、存储上传与文章所有权读取、死信重放状态机，以及 Agent 单轮与 WebSocket 生命周期协作者。事务边界必须显式区分权威事实、同库强一致副作用和可恢复投影：评论/关注通知与对应事实加入同一 MySQL 提交，缓存、搜索、RAG、作者计数与 timeline 则在提交后按 Outbox 或幂等投影收敛。

### 账号治理

- **关键入口**：[AuthController](../../apps/server/src/main/java/com/chtholly/auth/api/AuthController.java) → [AuthService](../../apps/server/src/main/java/com/chtholly/auth/service/AuthService.java) 兼容门面，再分派到注册、登录、Token 生命周期和密码恢复用例；公开用户与本人资料分别从 [UserController](../../apps/server/src/main/java/com/chtholly/user/api/UserController.java) 和 [ProfileController](../../apps/server/src/main/java/com/chtholly/profile/api/ProfileController.java) 进入；后台治理从 [AdminUserController](../../apps/server/src/main/java/com/chtholly/admin/api/AdminUserController.java) 与 [AdminPostController](../../apps/server/src/main/java/com/chtholly/admin/api/AdminPostController.java) 进入。
- **依赖与状态**：用户、`refresh_session_epoch`、登录日志和审计记录以 MySQL 为准；Redis 只保存验证码、原子发送配额、登录失败防护和带 TTL 的 refresh JTI membership。登录捕获 MySQL epoch、重读最新凭据，并在 Redis 条件写前后再次读取已提交 epoch；校验与轮换也双读，竞态时 compare-and-delete 本轮写入。注册由 [AuthRegistrationService](../../apps/server/src/main/java/com/chtholly/auth/service/AuthRegistrationService.java) 的外层 MySQL 事务约束用户创建、首枚 token 尝试与提交顺序，但 Redis membership 不参与 MySQL 原子提交；[PendingUserRefreshTokenStore](../../apps/server/src/main/java/com/chtholly/auth/token/PendingUserRefreshTokenStore.java) 只在当前事务看见 `epoch=1`、而独立已提交快照还看不见用户时写 `mysql:1`。JWT/Redis 签发失败会回滚用户；回滚或完成状态未知时 `afterCompletion` 会在确认没有已提交用户后 best-effort 清理本轮 membership。注册审计和 `UserRegisteredEvent` 只在 `afterCommit` 后分别 best-effort 执行，彼此失败不反向影响已提交注册；验证码一经成功验证即被消费，后续失败不恢复。密码变更使用“密码摘要 + epoch”单条 SQL，用户级撤销只推进 MySQL epoch；旧版裸 refresh membership 不迁移，V29 发布禁止新旧认证节点混部。[SecurityConfig](../../apps/server/src/main/java/com/chtholly/auth/config/SecurityConfig.java) 配置无状态 OAuth2 Resource Server，[BannedUserFilter](../../apps/server/src/main/java/com/chtholly/admin/security/BannedUserFilter.java) 在 JWT 后检查封禁。验证码与发送额度的新 key 都只保存目标摘要；验证码写入、TTL、一次性消费和失败次数由单 key Lua 线性化，发送失败按写入版本 compare-and-delete；新验证码保存时写 legacy fence，避免同目标旧明文值再次被兼容读取。非开发/测试 profile 没有本地明文投递回退。

### 内容生产

- **关键入口**：[PostController](../../apps/server/src/main/java/com/chtholly/post/api/PostController.java) 调用 [PostServiceImpl](../../apps/server/src/main/java/com/chtholly/post/service/impl/PostServiceImpl.java) 完成草稿、正文确认、元数据和发布；[TagServiceImpl](../../apps/server/src/main/java/com/chtholly/tag/service/impl/TagServiceImpl.java) 同步标签；[CommentController](../../apps/server/src/main/java/com/chtholly/comment/api/CommentController.java) 与 [CommentServiceImpl](../../apps/server/src/main/java/com/chtholly/comment/service/impl/CommentServiceImpl.java) 管理二级评论；[StorageController](../../apps/server/src/main/java/com/chtholly/storage/api/StorageController.java) 面向统一 [StorageService](../../apps/server/src/main/java/com/chtholly/storage/StorageService.java)，所有用户媒体均通过应用 multipart 入口完成草稿授权与内容校验，正文使用 `posts/{postId}/content-uploads/{random}.{type}` 不可变键，OSS 不向客户端签发裸 PUT。[`content`](../../apps/server/src/main/java/com/chtholly/content) 包的 [ContentIntelligenceReader](../../apps/server/src/main/java/com/chtholly/content/ContentIntelligenceReader.java) 是推荐与 Agent 读取内容分析的中立契约。
- **依赖与状态**：文章元数据、标签、评论、Outbox 与投影完成回执在 MySQL；Markdown 与媒体写本地文件系统或 OSS。[PostServiceImpl.confirmContent](../../apps/server/src/main/java/com/chtholly/post/service/impl/PostServiceImpl.java) 本身不声明事务；`prepareContentBinding` 以 `NOT_SUPPORTED` 挂起任何上层事务，在无事务阶段完成授权快照、键/大小/摘要、对象事实和 URL 验证，`bindPreparedContent` 再以 `REQUIRES_NEW` 进入独立短事务锁定草稿、复核所有者/状态并原子绑定元数据与 Outbox，不把对象下载或哈希放在 MySQL 行锁内。其他文章命令先锁聚合行并以状态 CAS 写事实；Caffeine/Redis、ES、RAG、作者计数和 timeline 都由 [PostOutboxProjectionProcessor](../../apps/server/src/main/java/com/chtholly/post/outbox/PostOutboxProjectionProcessor.java) 按当前事实幂等收敛。已有回执的重复事件直接跳过；旧事件在父 Outbox 仍存在但回执缺失时重跑投影并补回执而不回退游标，父行已清理时由游标高水位识别为迟到重复并跳过；只有较新事件在投影与回执成功后推进游标，较新事件缺少父行时回执写入失败、事务回滚并向上游传播。Kafka 消费者校验 Canal `aggregate_id` 与 payload `id` 强一致；严格个人页/关注作者缓存失效传播 Redis 异常，确保失败事件不写回执并可重放。完整 Kafka/Canal 模式以消费者作为低延迟主路径，[PostProjectionRecoveryJob](../../apps/server/src/main/java/com/chtholly/post/outbox/PostProjectionRecoveryJob.java) 仍在所有模式扫描仍存在且无回执的 Outbox 兜底。RAG 用每帖 Redisson watchdog 锁串行写入，先撤销 completion manifest、完整删除旧 chunks、写入并确认 refresh 无部分失败，最后才发布 manifest；查询仍逐条以 MySQL 可见性和内容摘要授权。

### 社区互动

- **关键入口**：[ActionController](../../apps/server/src/main/java/com/chtholly/counter/api/ActionController.java) → [CounterServiceImpl](../../apps/server/src/main/java/com/chtholly/counter/service/impl/CounterServiceImpl.java)；[RelationController](../../apps/server/src/main/java/com/chtholly/relation/api/RelationController.java) → [RelationServiceImpl](../../apps/server/src/main/java/com/chtholly/relation/service/impl/RelationServiceImpl.java)；[NotificationController](../../apps/server/src/main/java/com/chtholly/notification/api/NotificationController.java) 查询通知；[RecommendationController](../../apps/server/src/main/java/com/chtholly/recommendation/api/RecommendationController.java) → [RecommendationService](../../apps/server/src/main/java/com/chtholly/recommendation/RecommendationService.java)。
- **依赖与状态**：点赞/收藏由 [CounterReactionCommandService](../../apps/server/src/main/java/com/chtholly/counter/service/CounterReactionCommandService.java) 在同一 MySQL 事务写 `counter_reaction` 与 Outbox；Bitmap、SDS 和 `counter_snapshot` 都是派生投影。只有 Kafka 与 Canal 同时启用时才由 [CounterReactionOutboxConsumer](../../apps/server/src/main/java/com/chtholly/counter/event/CounterReactionOutboxConsumer.java) 消费 Canal-compatible Outbox；任一关闭时由 [CounterReactionLocalAdapter](../../apps/server/src/main/java/com/chtholly/counter/event/CounterReactionLocalAdapter.java) 在提交后处理，并由 [CounterReactionLocalOutboxReplay](../../apps/server/src/main/java/com/chtholly/counter/event/CounterReactionLocalOutboxReplay.java) 从 MySQL 恢复遗漏。共享 [CounterReactionEventProcessor](../../apps/server/src/main/java/com/chtholly/counter/event/CounterReactionEventProcessor.java) 以 `REQUIRES_NEW` 建立处理边界，[CounterAggregationProcessor](../../apps/server/src/main/java/com/chtholly/counter/event/CounterAggregationProcessor.java) 以 `REQUIRED` 加入同一事务，锁定 snapshot、登记 Inbox、计算快照并批量回查 MySQL 终态后维护 Redis 投影。事务提交后，每个尚无回执的真实 Outbox 变化都发布通知、Feed/作者计数和兴趣画像；[CounterReactionSideEffectReceiptService](../../apps/server/src/main/java/com/chtholly/counter/event/CounterReactionSideEffectReceiptService.java) 保存事件级发布回执，但不提供逐监听器 exactly-once。关注 Feed 由 [FollowingPostFeedQueryService](../../apps/server/src/main/java/com/chtholly/post/service/impl/FollowingPostFeedQueryService.java) 编排，Redis timeline 与大 V 缓存只发现候选，每批都由 MySQL 当前 active following、发布状态和可见性重新授权；Redis 候选不可用、深分页、扫描上限或候选不足时回退 MySQL 稳定分页。详情共享缓存命中也先读 MySQL audience 快照，`followers` 文章只对所有者或当前 active follower 开放。关系读缓存与兴趣画像主要在 Redis；关注写模型、通知和 Outbox 在 MySQL。

### 内容发现

### Agent 平台

- **关键入口**：[AgentWsTicketController](../../apps/server/src/main/java/com/chtholly/agent/api/AgentWsTicketController.java) 签发短期票据，[AgentWebSocketHandler](../../apps/server/src/main/java/com/chtholly/agent/ws/AgentWebSocketHandler.java) 只适配连接生命周期与协议分派；[ChthollyAgent](../../apps/server/src/main/java/com/chtholly/agent/ChthollyAgent.java) 是公开兼容门面，[AgentTurnOrchestrator](../../apps/server/src/main/java/com/chtholly/agent/runtime/AgentTurnOrchestrator.java) 编排单轮阶段，[AgentLoopExecutor](../../apps/server/src/main/java/com/chtholly/agent/runtime/AgentLoopExecutor.java) 只保留循环状态迁移。[ContextEngine](../../apps/server/src/main/java/com/chtholly/agent/context/ContextEngine.java) 组装上下文，[AgentTool](../../apps/server/src/main/java/com/chtholly/agent/AgentTool.java) 定义工具契约，[AgentMemoryStore](../../apps/server/src/main/java/com/chtholly/agent/memory/AgentMemoryStore.java) 保存会话记忆。站内、Bangumi 与公网研究工具位于 [agent/tools](../../apps/server/src/main/java/com/chtholly/agent/tools)，公网 URL、DNS pinning、redirect、robots 和正文抽取边界位于 [agent/web](../../apps/server/src/main/java/com/chtholly/agent/web)。`llm` 包以 [LlmConfig](../../apps/server/src/main/java/com/chtholly/llm/LlmConfig.java)、[RagIndexService](../../apps/server/src/main/java/com/chtholly/llm/rag/RagIndexService.java) 和 [RagQueryService](../../apps/server/src/main/java/com/chtholly/llm/rag/RagQueryService.java) 适配模型与 RAG。
- **依赖与状态**：核心 Agent、WebSocket、工具执行和 Redis/Caffeine 会话记忆受 `llm.enabled` 控制；内容、图谱、学习、经验、情绪、社区动作和主动行为再由 `agent.extensions.*.enabled` 分组控制。公网工具仅在明确外部研究意图下暴露，搜索不产生 Evidence，只有命中本轮累计搜索候选的安全抓取正文才可完成该研究链；正文编码会按合法 charset 解码，同 URL 的内容新版本会更新既有 citation 绑定。复合 Bangumi 任务的必需工具成功后进入 `SATISFIED`；provider `ERROR`、`TIMEOUT` 或 `INTERRUPTED` 进入 `BLOCKED`，不会被完成门槛反复拒绝到最大步数。本轮已有 Evidence 时只能据此收束并说明缺失，没有可回答 Evidence 时只说明 provider 不可用；参数 `VALIDATION_ERROR` 仍保持待修正。失败工具调用只产生受控 Observation，不产生 Evidence。用户和 provider/host 配额复用 Redis 限流器，不新增密钥或必需配置。`LLM_ENABLED=false` 时 `NoOpPostRagIndexer` 保留文章发布主链，博客与社区不依赖 Agent 启动。
- **代表性测试**：[AgentWebSocketHandlerTest](../../apps/server/src/test/java/com/chtholly/agent/ws/AgentWebSocketHandlerTest.java)、[AgentWebSocketArchitectureTest](../../apps/server/src/test/java/com/chtholly/agent/ws/AgentWebSocketArchitectureTest.java)、[ChthollyAgentTest](../../apps/server/src/test/java/com/chtholly/agent/ChthollyAgentTest.java)、[AgentLoopCompletionPolicyTest](../../apps/server/src/test/java/com/chtholly/agent/runtime/AgentLoopCompletionPolicyTest.java)、[BangumiToolFailureContractTest](../../apps/server/src/test/java/com/chtholly/agent/tools/BangumiToolFailureContractTest.java)、[AgentLoopExecutorArchitectureTest](../../apps/server/src/test/java/com/chtholly/agent/runtime/AgentLoopExecutorArchitectureTest.java)、[ContextEngineTest](../../apps/server/src/test/java/com/chtholly/agent/context/ContextEngineTest.java)、[AgentToolPlannerTest](../../apps/server/src/test/java/com/chtholly/agent/runtime/AgentToolPlannerTest.java)、[SafeWebHttpClientTest](../../apps/server/src/test/java/com/chtholly/agent/web/SafeWebHttpClientTest.java)、[AgentMemoryStoreTest](../../apps/server/src/test/java/com/chtholly/agent/memory/AgentMemoryStoreTest.java)。
- **修改联动**：消息协议要同步 WebSocket 前端；上下文贡献者需保持顺序和 Core-only 契约；工具参数、超时、Trace 与记忆键/TTL 改动要成组验证。

### 内容初始化

- **关键入口**：命令行 [SeedRunner](../../apps/server/src/main/java/com/chtholly/seed/SeedRunner.java) 解析 mode/dry-run，[SeedOrchestrator](../../apps/server/src/main/java/com/chtholly/seed/SeedOrchestrator.java) 构建并持久化计划；[AdminSeedAuditController](../../apps/server/src/main/java/com/chtholly/admin/api/AdminSeedAuditController.java) 只暴露审计结果。
- **依赖与状态**：幂等 marker、账号、文章、评论、关注、推荐数据及可选点赞/收藏关系写入 MySQL；正文可经 `SeedContentPublisher` 写存储；互动在线投影由正式校准链路从 MySQL 重建；已发布种子文章在 ES 可用时立即索引。
- **代表性测试**：[SeedRunModeTest](../../apps/server/src/test/java/com/chtholly/seed/SeedRunModeTest.java)、[SeedOrchestratorTest](../../apps/server/src/test/java/com/chtholly/seed/SeedOrchestratorTest.java)、[SeedContentAuditorTest](../../apps/server/src/test/java/com/chtholly/seed/SeedContentAuditorTest.java)。
- **修改联动**：新增模式或字段要同步 `SeedMapper` SQL、幂等 marker、dry-run 摘要和审计；生成内容不得绕过正式发布所依赖的数据约束。

### 平台基础

- **关键入口**：启动类 [ChthollyApplication](../../apps/server/src/main/java/com/chtholly/ChthollyApplication.java)；`common` 包的 [GlobalExceptionHandler](../../apps/server/src/main/java/com/chtholly/common/web/GlobalExceptionHandler.java)、[AbstractKafkaConsumer](../../apps/server/src/main/java/com/chtholly/common/kafka/AbstractKafkaConsumer.java) 和限流/调度基础件；`config` 包的 [ElasticsearchConfig](../../apps/server/src/main/java/com/chtholly/config/ElasticsearchConfig.java)、[RedissonConfig](../../apps/server/src/main/java/com/chtholly/config/RedissonConfig.java) 与 [ThreadPoolConfig](../../apps/server/src/main/java/com/chtholly/config/ThreadPoolConfig.java)；`health` 包的 [ElasticsearchHealthIndicator](../../apps/server/src/main/java/com/chtholly/health/ElasticsearchHealthIndicator.java)、[BangumiHealthIndicator](../../apps/server/src/main/java/com/chtholly/health/BangumiHealthIndicator.java) 和 [OssHealthIndicator](../../apps/server/src/main/java/com/chtholly/health/OssHealthIndicator.java)。
- **依赖与状态**：本领域不拥有业务数据；它定义跨领域的错误格式、配置 Bean、线程池、重试/死信、可观测性与健康探针。健康指标反映依赖状态，不替代业务降级策略。
- **代表性测试**：[BackendArchitectureFitnessTest](../../apps/server/src/test/java/com/chtholly/architecture/BackendArchitectureFitnessTest.java)、[GlobalExceptionHandlerTest](../../apps/server/src/test/java/com/chtholly/common/web/GlobalExceptionHandlerTest.java)、[AbstractKafkaConsumerTest](../../apps/server/src/test/java/com/chtholly/common/kafka/AbstractKafkaConsumerTest.java)、[ElasticsearchHealthIndicatorTest](../../apps/server/src/test/java/com/chtholly/health/ElasticsearchHealthIndicatorTest.java)、[DegradationGoldenPathIT](../../apps/server/src/test/java/com/chtholly/integration/DegradationGoldenPathIT.java)。
- **修改联动**：通用错误、线程池、Kafka 重试、配置默认值或健康语义变化会跨领域影响调用方，必须搜索所有消费者并补充集成验证。
